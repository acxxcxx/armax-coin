## 1. Executive Summary & Purpose

Armaxcoin v1.0.8 is a dedicated maintenance and operational security release resolving critical user-facing issues in the Desktop GUI wallet and hardening node privacy across both Linux/Unix and Windows environments.

The release resolves four key issues:

1. **Linux Desktop GUI Authentication Failure:** Resolves the `{"error":"Unauthorized: Invalid or missing GUI session token"}` failure when creating a new wallet on Linux desktops (Ubuntu, Xubuntu, Debian, Arch, and VPS deployments).
2. **Missing First-Time Wallet Onboarding Flow:** Replaces the unhandled empty wallet state (`undefined` address and zero balance) with an interactive onboarding modal and overview card for encrypted keystore creation and mnemonic restoration.
3. **P2P Node Privacy & Residential IP Protection:** Prevents residential node and home miner public IP addresses using ephemeral outbound ports from leaking into GUI active peer displays.
4. **Snapshot Tooling Precedence Fix:** Fixes flag precedence in public snapshot creation scripts (`make_public_snapshot.ps1` and `make_public_snapshot.sh`) so that explicit `-SkipGitleaks` flags are honored when synthetic test fixtures are present.

## 2. Problem Statement & Root Cause Analysis

### A. Linux GUI Wallet Authentication Failure
* **Symptoms:** In Linux GUI v1.0.7, clicking "Create Encrypted Keystore" resulted in `Wallet creation failed: {"error":"Unauthorized: Invalid or missing GUI session token"}`.
* **Root Cause:** In `gui/main_unix.go`, the backend generated a cryptographically secure 32-byte session token at startup and enforced token validation via `secureGUIHandler` on all `/api/*` endpoints. However, the token was neither injected into the HTML template nor sent as an HTTP cookie. Consequently, frontend `fetch()` requests were dispatched without the `X-Armx-GUI-Token` header, causing the middleware to reject requests with HTTP 401 Unauthorized.

### B. Undefined Address & Lack of First-Time Onboarding
* **Symptoms:** When launching the GUI without an existing `testnet/wallet.json`, the active address was displayed as `undefined`, and no modal or wizard appeared to guide the user to create or restore a wallet.
* **Root Cause:** `/api/wallet/info` returned `{"address": ""}` when no keystore existed. The frontend JavaScript attempted to read `data.address` directly without null/empty checking, resulting in JavaScript evaluating `undefined` or setting empty DOM text without triggering an onboarding modal.

### C. Residential Peer IP Leakage
* **Symptoms:** When a residential node connected inbound to a public seed or node, the node reported the peer's remote socket with an ephemeral port assigned by the OS (e.g. `198.51.100.25:58539`). The GUI displayed this endpoint in "Connected P2P Mesh" and active `/peers` listings.
* **Impact:** Displaying non-listening ephemeral ports exposed the residential public IP addresses of home miners and casual participants.

## 3. Detailed Technical Solutions

### A. Multi-Layer GUI Session Authentication (`gui/main_unix.go`)
1. **HTML Template Token Injection:** When serving `handleWebUI` (`/`), the server injects the active session token directly into the client-side JavaScript execution context:
   ```html
   <script>const GUI_SESSION_TOKEN = "{{SESSION_TOKEN}}";</script>
   ```
2. **Secure Cookie Issuance:** The server sets an `HttpOnly`, `SameSite=Strict`, `Path=/` session cookie named `armax_gui_token` upon initial Web UI page load.
3. **Transparent Fetch Interception:** Client-side JavaScript wraps `window.fetch` to automatically append the `X-Armx-GUI-Token` header to all relative `/api/*` requests.
4. **Multi-Channel Middleware Acceptance:** `secureGUIHandler` checks for credentials across three compliant channels:
   - Request Header: `X-Armx-GUI-Token`
   - Secure Cookie: `armax_gui_token`
   - Query Parameter: `?token=` (fallback for direct browser downloads like `/api/export-csv`)
5. **DNS Rebinding Protection Preserved:** Strict validation of the `Host` header (`127.0.0.1`, `localhost`, `::1`) remains fully enforced.

### B. First-Time Wallet Onboarding UI (`gui/main_unix.go`)
1. **Clean Initial State:** `/api/wallet/info` explicitly returns `{"address": "", "initialized": false}` when keystore does not exist.
2. **Onboarding Overview Banner (`#noWalletCard`):** An alert banner is displayed on the Overview tab prompting the user to either create an encrypted keystore or restore from seed.
3. **Automated Setup Modal (`#setupWalletModal`):** Automatically pops up on first launch when no active address is detected, providing passphrase validation (minimum 12 characters) and generating a new 24-word BIP-39 mnemonic with an ML-DSA-65 post-quantum address.
4. **Mnemonic Restoration Modal (`#restoreWalletModal`):** Enables importing existing 24-word seed phrases directly within the web GUI.
5. **Dynamic State Refresh:** Onboarding modals seamlessly close and update the UI upon successful wallet creation without requiring a manual browser refresh.

### C. Active P2P Peer Display Privacy Filter (`gui/main.go`, `gui/main_unix.go`)
1. **Filter Implementation:** Added `isSafeP2PDisplayPeer` and `filterSafePeersJSON` to sanitize peer lists across:
   - `/api/peers` and `/api/peers?filter=active`
   - Console command `getpeerinfo`
   - Diagnostics tab `/peers` inspection
2. **Display Criteria:**
   - **DNS Seeds:** Domain hostnames and default seeds are always displayed.
   - **Public Nodes:** Public IP addresses are displayed **only** if their port matches the network's open listening P2P port (`19335` for testnet, `19334` for mainnet).
   - **Home Nodes Protected:** Ephemeral client ports (e.g. `:58539`, `:49152`) are strictly stripped from display.
   - **Localhost Development Preserved:** Loopback addresses (`127.0.0.1`, `localhost`, `::1`) remain visible for local development and unit tests.

### D. Snapshot Script Precedence Order (`scripts/make_public_snapshot.*`)
In `make_public_snapshot.ps1` and `make_public_snapshot.sh`, the check for explicit skip flags (`-SkipGitleaks` / `--skip-gitleaks`) was moved ahead of the `gitleaks` executable check, ensuring tests and operators can bypass gitleaks scans when intended.

## 5. Upgrade & Deployment Instructions

### For Linux Desktop Users:
1. Download the v1.0.8 release archive:
   ```bash
   tar -xzf armax-v1.0.8-linux-amd64.tar.gz
   cd armax-v1.0.8-linux-amd64
   ```
2. Launch the Desktop GUI wallet:
   ```bash
   ./armgui
   ```
3. The system default browser will open to `http://127.0.0.1:18088`. If no wallet exists, the onboarding dialog will automatically prompt you to create or restore a wallet.

### For Node Operators & Miners:
- v1.0.8 is wire-compatible and consensus-compatible with v1.0.7.
- Upgrading to v1.0.8 is recommended to benefit from peer privacy protections and GUI stability.
